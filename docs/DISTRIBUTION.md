# 配布用コピーの作成と公開確認

開発者向けに、配布候補ZIPの生成方法と公開時の確認事項を説明する。配布コマンドは普段使いのデータから分離した候補を生成し、Git操作やアップロードは行わない。NexusArk本体のフォルダも変更しない。

利用・ダウンロードの案内は [README](../README.md)、現在の公開版は [GitHub Releases](https://github.com/POKAZINE/Emerald-Arcade/releases) を参照。

## 専用コマンド

GameAppsフォルダで実行する。Node.js 22.13以降が必要。追加パッケージは不要。

```powershell
npm run release:check
npm run release:build
```

PowerShellでnpmのスクリプト実行が制限される環境では、`npm.cmd run release:build` を使うか、`node --no-warnings scripts/release.mjs` を実行する。OSの実行ポリシーを変更する必要はない。

- `release:check` は収録対象・参照先・既知の秘密情報・構文を確認し、tests内の全テストを実行する。ZIPは作らず、新規起動の確認はbuildで行う。テストは隔離したtest-outputを使用する。
- `release:build` は上記に加え、日本語と空白のある作業フォルダへ配布ファイルをコピーし、別ポート・新規のdataで起動する。新規設定・記録0件・私用問題なし・外部接続OFF・新しいキーの生成と全publicファイルの配信を確認してからZIPを作る。
- 普段のサーバーは停止・再起動しない。NexusArkへの接続・会話送信や、既存の設定・対局の変更もしない。ローカルの保存済みキーと私用問題本文は、混入検査の照合用としてのみ読み、出力しない。

出力は `release/Emerald-Arcade-版番号-preview-UTC日時-識別子/` に保存する。毎回別フォルダとなり、以前のZIPは上書きしない。作業中のコピーは終了時に除去するが、既存のdataや過去の生成物は削除しない。

| 出力 | 内容 |
| --- | --- |
| `Emerald-Arcade-….zip` | 展開して使う配布候補。ZIP内はEmerald Arcadeという1フォルダにまとまる |
| `….zip.sha256` | ZIPのSHA-256 |
| `PACKAGE-MANIFEST.json` | 各収録ファイルの相対パス・サイズ・SHA-256。ZIP内にも同梱。自分自身は集計対象外 |
| `CHECK-REPORT.json` | テストと初期起動の結果、公開前に人が確認する項目。秘密キーや個人環境の絶対パスは含めない |

previewは公開前の候補であることを示す。生成成功だけを理由に公開しない。

## 何を収録するか

`release.config.json` が基準となる。

- publicとlibは再帰的に収録する。新ゲームのJS・CSS・HTML・ルール・既知形式の素材は自動で増やせる。
- サーバー・起動停止ファイルを収録する。package.jsonは遊ぶ人向けの起動コマンドだけに整理して生成する。
- 説明書はdistribution/README.mdをZIPのREADME.mdとして収録する。開発用READMEとdocs全体はコピーしない。配布文書を増やす場合はconfigのdocumentsへ追加する。
- LICENSE等の指定されたライセンス・出典ファイルが存在すれば収録する。独自の個人利用条件をLICENSE.mdに記載する。コマンドが新しいライセンスを自動で付与することはない。
- data・test-output・開発資料・確認画像・ログ・バックアップ・node_modules・Git履歴は収録しない。

未知のルート直下の項目、素材形式、収録対象内の隠しファイル／秘密ファイル／リンク、欠けた静的参照、外部依存が見つかった場合は停止する。新しい構成に気づかず不完全なZIPを作らないためである。256MiBを超える場合やZIP64が必要な場合も、生成方式の見直しを案内して停止する。

検査は既知の保存済みキー・私用問題の一致、明らかな秘密キー、個人環境の絶対パスを対象とする。すべての私的な文章や個人情報を自動判別する機能ではない。ソースへ個人情報を書かないことと、人による収録一覧の確認は引き続き必要。

## 新ゲームを追加するとき

1. 画面と素材はpublic、サーバー側ルールと固定問題はlibへ追加する。個人用の問題・記録・設定はdataへ置く。
2. 画面から必要な素材を配信できるようサーバーの静的ルートも追加する。起動確認は全publicファイルの配信を検査する。
3. ルール・秘密情報の公開範囲・通知・復旧・記録と共有の対応、PC／スマホの操作を確認し、testsに必要な検証を追加する。新テストはコマンドが自動で実行する。
4. 外部素材やライブラリを導入した場合はdocs/ASSET_SOURCES.mdに出典と利用条件を記録する。新しいディレクトリ・拡張子・依存を導入した場合はrelease.config.jsonと生成方法を見直す。
5. release:buildを実行し、生成物の一覧とレポートを確認する。実際にZIPを別フォルダへ展開して使う確認も行う。

## 私用の創作問題

原案・真相はdata/private-lateralにあり、遊んだ場合はSQLiteの対局・履歴にも複製が残る。ボタンの非表示だけで配布準備完了とはしない。コマンドはdata全体を除外するため、私用問題のない初期状態となり、一時的な選択・管理ボタンは表示されない。内部の対応コードは残す。

手元の問題・記録を削除して配布版を作らない。個人用の管理画面画像を含むdocsも収録しない。

## 公開直前に人が確認すること

- 正式名称・非公式表記、ライセンス、素材・コードの利用条件、説明書の「公開前候補」の文言。
- 対応確認したNexusArkの版と日付、実際の連携画面名・手順。フォルダ名に依存せず、別名の設置場所から使えること。
- 新規利用者の初回設定、全ゲームの基本動作・秘密の扱い、スマホ表示と任意のLAN接続。
- 更新時に利用者のdataを残す手順。新規ZIPを既存データのあるフォルダへ自動展開しない。
- 収録一覧とZIPの展開結果。実際の会話・個人名・私用問題・Tokenがないこと。
- GitHubでソースも公開する場合は、管理対象とコミット履歴を別途確認する。このコマンドはGit履歴を監査しない。.gitignoreはZIP作成・過去のコミットの除去を代行しない。

本体とGameAppsを同階層に置くのは整理上の推奨であり、必須条件ではない。本体の自動検索・自動編集・自動起動、ファイアウォール等の設定変更は配布のために追加しない。

### 確認済みの内容

| 項目 | 確認結果 |
| --- | --- |
| 自動テスト | 247件合格。隔離データ・模擬接続を使用 |
| 配布用コピーの起動 | 別ポート・新規dataで起動し、初期設定・記録0件・私用問題なし・LAN初期OFF・キーの新規生成・静的ファイル配信を確認 |

| 初回導入の説明 | READMEにNode.jsの確認・導入、Start.batとStop.bat、API／MCP設定の案内を記載 |

| ソースの公開 | 選別した164ファイルの初回コミットから開始。過去の開発履歴や個人データを持ち込まず、PUSH先のコミット一致を確認 |
| 利用条件 | LICENSE.mdを同梱。公開用READMEにも要約を記載 |
| リリースの公開 | 試用版として公開し、タグの対象コミットと、認証なしで取得したZIP・チェックサムのハッシュを照合 |

ZIPのSHA-256はリリースページと添付のチェックサムを参照。後続版へ、この確認結果をそのまま引き継がない。

### 確認範囲と未確認事項

- 全18ゲーム・全設定を、このリリースのZIPで実ペルソナと再確認したものではない。自動テストの合格はモデルの戦略の強さや操作の確実性を保証しない。
- 本体の版情報は設置環境の確認結果。公式配布版との同一性、他のNexusArk版、すべてのモデル・設定との互換性は未確認。
- 名称・素材・文章は [公開候補の点検](PUBLICATION_REVIEW.md) に調査範囲を記載。全名称の商標等を網羅して権利上の問題がないと認定したものではない。
- 個人情報の検査は既知の名前・保存済み秘密情報等との照合。未知の別名や任意の個人情報をすべて自動判定するものではない。

## 次回以降の公開チェック

新しい版を公開するときは、対象のコミット・ZIP・確認日を特定して、以下を改めて確認する。未実施の確認を合格扱いにせず、残る制限はリリース説明へ記載する。

- [ ] 対象ZIPの収録一覧・ハッシュと、対応するソースのコミットを照合する。
- [ ] 別フォルダで新規起動し、個人データ・私用問題・Tokenが混入していないことを確認する。
- [ ] Node.js導入・起動停止・APIとMCPの設定・更新時にdataを残す手順を確認する。
- [ ] 変更したゲームと共通機能を、必要なPC／スマホ環境・採用ルールで確認する。
- [ ] 確認したNexusArkの版・モデル・日付と、未確認範囲を記録する。
- [ ] 利用条件、追加した素材・依存・名称・説明文の出典や利用条件を確認する。
- [ ] Gitの管理対象と履歴を確認する。既存の履歴がある場合は、秘密情報を持ち込んでいないか別途調査する。
- [ ] READMEとリリース説明を公開形態に合わせて更新する。
- [ ] 公開後、認証なしのダウンロードとチェックサム・タグを確認する。
